# 体验外呼

两条线不能混：打给用户指定的手机号，或打给登录账号绑定的手机号。不要用「列出标杆」代替拨打。体验外呼免费。需要登录的走 `authentication.md`。

对用户只讲：打给谁、是不是真电话、验证码、已受理还是没打成。不要念错误码、不要说已经接通、不要说可以查通话状态。

## 打给指定手机号

命令前先展示并得到明确确认，没确认不要发命令：

- 目标标杆（用 CLI 返回的名称；id 只给命令用）
- 完整目标手机号（给用户核对，不要脱敏）
- 会打出一通真实的免费体验电话
- 这还不是已经接通

确认后再发：

```bash
whobot trials start <id> --phone <phone> --json
```

`ok=true` 且 `data.status=verification_required` 表示要先过短信，不是失败。记住 `data.verificationId`（`verify_` 开头）。

告诉用户：验证码会进入这次对话。请把短信里的 6 位数字发给我。然后：

```bash
stdin | whobot trials verify <verificationId> --code-stdin --json
```

验证码只能从 stdin 进，不要写在命令参数里。不要用登录验证码走这条线。

失败后不要偷偷换号码、换账号、换网页通话，也不要换一套本地配置再打同一通。

## 打给账号绑定的手机号

先登录。跑 `whobot auth status --json`，确认已登录，记下脱敏手机号和企业。这条线不要让用户改号码，命令不要加 `--phone`。不要在这里再要登录验证码。

命令前展示并确认：

- 目标标杆（名称；id 只给命令用）
- 脱敏手机号（用 `auth status` 的 `phoneMasked`，不要编完整号码）
- 会打出一通真实的免费体验电话
- 这还不是已经接通

确认后再发：

```bash
whobot trials start <id> --json
```

失败后不要改成加 `--phone` 重试，也不要改成网页通话。需要登录或重新授权时走 `authentication.md`。

## 打出去之后

`data.status=accepted` 只表示已经受理，不是接通、完成，也不能拿去查通话。

| 情况 | 对用户说 | 接下来 |
| --- | --- | --- |
| 已受理 | 已经提交，电话稍后打出；现在还不能查通没通 | 停 |
| 验证码不对 | 验证码不对 | 等用户再给，不要自己连打 |
| 验证码过期 | 验证码过期了 | 重新确认后再发起 |
| 还在处理 | 上一通还在处理 | 等，不要新开一通、不要换号 |
| 结果未知 | 这通结果不确定 | 不要自动再打 |
| 暂时限流 | 请稍后再试 | 按返回的等待时间，不要自己空转 |
| 需要登录 | 需要先登录 | 走 `authentication.md` |

未知错误：停。不要根据中文说明猜下一步。
